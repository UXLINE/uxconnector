UXConnector 2.18.0 - validation summary
Date: 2026-09-17

Implemented hardening
- Webhook key query-string disabled by default; temporary compatibility flag available.
- Existing X-UXConnector-Webhook-Key header remains compatible.
- Optional HMAC-SHA256 + timestamp freshness verification.
- Optional outbound host allowlist (exact hosts and *.subdomain patterns).
- Built-in Zendesk template IDs locked to their intended GLPI target types.
- Configurable record safety ceiling: 50,000 scheduled inbound records by default.
- Configurable record safety ceiling: 50,000 records per webhook by default.
- Zendesk synthetic volume harness updated with the ticket template id.

Validation performed
- PHP syntax check over src/, front/, tools/ and tests/: PASS.
- PHP-CS-Fixer applied to modified PHP files: PASS.
- HMAC authentication smoke test: PASS.
- Built-in Zendesk target policy smoke test: PASS.
- Zendesk synthetic 20,000-ticket / 100-per-page test:

    Processed: 20,000

    Writer count: 20,000
    Peak memory: 4 MiB in this harness
  Result: PASS.

Environment limitation
- Full PHPUnit suite could not be executed in the artifact container because its PHP CLI
  lacks DOM, mbstring and xmlwriter extensions required by PHPUnit. The new tests are
  included in the package and should be run in the normal GLPI/CI PHP 8.2 environment.

Compatibility notes
- Zendesk polling imports are not dependent on webhook HMAC and remain operational.
- User, Group, Entity, ITILCategory, Ticket, ITILFollowup and Document writer support remains present.
- Legacy webhook ?key=... calls require UXCONNECTOR_ALLOW_LEGACY_WEBHOOK_QUERY_KEY=1.
- HMAC enforcement is opt-in with UXCONNECTOR_REQUIRE_WEBHOOK_HMAC=1 so header-based
  legacy webhooks are not broken by the upgrade.
